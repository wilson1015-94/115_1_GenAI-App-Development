# 第 8 週｜期中個人小專題（課堂簡化版）

2026-11-04 更新：期中專題統一放在自己 GitHub Repo 的 `Midterm Mini-Project` 資料夾；部署到 Streamlit Community Cloud 為必做，保留 JSON Schema／Pydantic 擇一路線。**最低要求固定，題目與設計開放。** 這週要把前面學過的能力做成自己的小工具。
原專題說明書、原 starter、原教師摘要器保留作比較；本週授課以此修訂版為入口。

## 1. 本週定位與學習目標

第 3／4 週學會 API 與任務規則，第 6 週學會 Schema 與回應檢查，第 7 週學會表單、按鈕、狀態。
本週整合成一個有明確使用者與用途的工具：**輸入→規格→處理→檢查→結果**。
學生要能說明自己的任務與欄位設計、獨立修改程式，並用實際測試判斷輸出是否可用。
本週以 VS Code／本機專案操作；不在 Notebook 或 Colab 直接啟動 Streamlit。
第 9 週再擴充 PDF／Word／CSV 文件讀取、清理與分塊；本週文字貼上即可完成最低要求。

## 2. 哪些固定，哪些自己決定

| 老師固定的最低成果 | 學生自行決定 |
|---|---|
| 個人完成可操作的 Streamlit App | 題目、目標使用者、使用情境 |
| 至少一項主要功能呼叫 OpenAI API | 輸入資料、表單欄位、任務 prompt |
| 至少一項真正 Structured Outputs | 輸出欄位與用途、畫面呈現 |
| 輸入與回應檢查、金鑰保護 | 採用 starter、自行撰寫或改造自己的舊作 |
| 部署到 Streamlit Community Cloud，提供老師可開啟的 App 網址與雲端驗收紀錄 | App 名稱、畫面與功能特色 |
| 自己的 GitHub Repo 根目錄下建立 `Midterm Mini-Project`，包含程式、README與測試紀錄，並完成3～5分鐘Demo | 延伸功能與特色 |

**starter 是可選用的起點，不是統一題目或全班共同填空作業。** 不使用 starter 不扣分，驗收標準相同。
教師摘要器不可只換標題或 prompt 後繳交。請提出自己的使用情境，讓輸入、規則、欄位與畫面確實服務該情境。
選同樣題目也可以，但必須能說明個人的設計決策、實際修改與測試結果。

## 3. 最低要求與選做

必做：一個任務、清楚的輸入與送出按鈕、至少兩個有用途的結構化欄位、依欄位呈現的結果。
結構化輸出可擇一採用：JSON Schema 的 `text.format`／`json_schema`／`strict=True`，或 Pydantic 的 `responses.parse(text_format=模型類別)`。
兩種起點與教師範例皆已提供，驗收與評分相同，不必完成兩版；只在 prompt 寫「回 JSON」不算。
金鑰只能放 `.env` 或 Secrets；repository 排除 `.env`、`.streamlit/secrets.toml`、`.venv/`、`__pycache__/`。
API 預設關閉，使用者明確開啟並提交才請求；輸入不合格不能發出請求，錯誤不能冒充成功。
**部署到 Streamlit Community Cloud 為必做**；本機可執行仍須保留，但不能取代雲端驗收。

選做：文字檔上傳、streaming、聊天、usage／成本估算。先完成核心任務與部署，再依需要擇一延伸。
檔案上傳須檢查大小、編碼與長度，錯誤不能默默漏字；串流須處理完成、失敗與連線收尾，部分文字不能視為完成結果。
延伸功能依既有評分項目反映品質，總分仍為 100，不因沒有選做而缺少最低要求分數。

### 3-1. 部署到 Streamlit Community Cloud（必做）

部署步驟回查[Git 與 GitHub 通用指南第 9 節](../week07/生成式AI應用開發_第07週_Git實作教材_學期共用Repo版.md)。本週依序完成：

1. 將自己的 App、README 與 requirements 放在自己 GitHub Repo 根目錄的 `Midterm Mini-Project` 資料夾內，再 Commit／Push；到 GitHub 確認部署分支上的檔案與路徑正確。
2. 在 Streamlit Community Cloud 建立 App，選對自己的 Repo、分支與 Main file path。若入口為本資料夾內的 `app.py`，填 `Midterm Mini-Project/app.py`，保留資料夾名稱中的空格。這是學生繳交路徑，與教材 README 示範的原始教材路徑不同；自行調整程式結構者填實際入口路徑。
3. 將 `requirements.txt` 放在入口程式同層或 Repo 根目錄，採用所選路線的套件清單；已有共用清單先比較，不直接覆蓋。Pydantic 路線須包含 Pydantic。
4. 在 Advanced settings 選擇平台可用且經實測的 Python 版本，依 `.streamlit/secrets.example.toml` 填入平台 Secrets。金鑰不放 GitHub，不能只靠本機 `.env` 宣稱雲端設定完成。
5. 等安裝與啟動完成，用 App 網址檢查輸入、結果與錯誤顯示。啟用 API 後，至少在雲端成功處理一筆虛構原文，記錄實際輸入、輸出、日期、模型與請求數，並逐欄核對。
6. 把 App 網址及驗收紀錄寫進自己的 README 與設計表；確認老師能開啟。若限制存取，須先設定老師的觀看權限；介面上的 API 開關不等於觀看權限設定。

**部署完成條件：老師可開啟網址、雲端介面可操作、至少一筆雲端真實 API 成功結果可核對。** 只有本機展示或產生網址，均不足以完成部署驗收。
正常／資訊不足兩筆測試可直接在雲端完成，不必本機再做一次；若先前只在本機測過，補一筆雲端成功測試並記錄追加請求數。
部署或權限問題須記錄錯誤與待補驗項目，依老師公告期限補齊；填「未部署／未測」不等於完成必做要求。

## 4. 先設計，再操作範例

先填 [專題設計與驗收紀錄](第08週_課堂簡化版_專題設計與驗收紀錄.md)。
選題可從「社團公告整理」「活動報名訊息分類」「求職資料整理」發想，也可自訂。
這些只是方向，不指定固定欄位或標準答案。先問：誰在什麼情境需要它？輸入是什麼？哪些欄位能幫他下一步操作？
先縮成一個能展示的任務，完成核心功能後接著部署；聊天、資料庫與檔案上傳不必一次加入。

## 5. 完整示範與學生起步

教師先選一份完整摘要器，展示原文、資料契約、送出、結果與人工核對。
教師示範不依賴學生完成任何 TODO。先關閉 API 看輸入檢查，再開啟示範一次真實結果。

| 路線 | 學生起點 | 教師完整範例 |
|---|---|---|
| JSON Schema（現有版保留） | [學生起點](week08_midterm_simple_starter/README.md) | [完整摘要器](week08_midterm_simple_teacher/README.md) |
| Pydantic（新增） | [學生起點](week08_midterm_simple_pydantic_starter/README.md) | [完整摘要器](week08_midterm_simple_pydantic_teacher/README.md) |

學生擇一或自行實作；四個專案皆可獨立執行，從自己的資料夾依 README 建立 Python 3.14 虛擬環境並啟動。
兩份教師例使用相同原文輸入與 title／summary／key_points 三欄，便於比較；學生仍須設計自己的任務與欄位。
先讀[兩種版本對照](第08週_課堂簡化版_JSON_Schema與Pydantic對照.md)，再選擇起點，不必把兩版程式混在一起。

API 流程已提供，學生不必先完成通用 helper 框架。起步程式只保留兩個短函式，主流程由上往下閱讀。
起點支援 string 與 array of string，足以完成小工具；需要布林、數字、nullable、enum、巢狀資料者可自行擴充並補驗證。

## 6. A／B／C 是設計任務，不是指定題目的填空

| 任務 | 已提供 | 學生負責／保存位置 | 完成條件 |
|---|---|---|---|
| A：任務定位 | API 呼叫與錯誤分流 | 自選題目；APP_TITLE、INSTRUCTIONS 為 str | 有使用者、明確任務、只依原文與資訊不足處理規則 |
| B：資料契約 | strict 請求、解析、基本型別檢查 | JSON Schema版填SCHEMA；Pydantic版定義ProjectResult；至少兩個有用途欄位 | 全部欄位必填、禁止多餘欄位，型別與檢查對齊；欄位確實服務自己的題目 |
| C：操作與呈現 | 表單、結果保存、通用欄位顯示 | FIELD_LABELS 為 dict[str,str]；按需要修改輸入與結果區 | 標籤讓使用者看得懂；能對照輸入解釋每個結果 |

順序 A→B→C→離線檢查→真實測試→Cloud 部署與驗收→README／Demo；真實測試也可在部署後直接於雲端完成。自行實作者交付同等成果即可。
JSON Schema版解析後取得 `data`（dict）；Pydantic版取得 `output_parsed` 物件，再以 `model_dump()` 轉成 `data`。
驗證後才保存 `st.session_state.record`（原文＋data）；錯誤另存 `error`（str）。
這些變數是起點的讀法，不是評分必須使用的名稱。不要只 print 後宣稱已完成可操作 App。
讀設定與既有回應檢查可保留；改型別或欄位時要同步檢查、顯示與測試，不能只改 Schema 或模型。
字典、list、items、JSON 與例外回查第 2／6 週；form 與 state 回查第 7 週，這週不另教框架。

## 7. 先離線檢查，再記錄真實成果

| 檢查 | 操作與預期 | 證據界線 |
|---|---|---|
| 空白／過長 | API 關閉，送出空白與 6001 字元；出現提示 | 0 次請求，只證明輸入檢查 |
| 設計未完成 | starter 尚未設定 A／B 時送出正常文字；提示完成設計 | 0 次請求，不能當成果 |
| 正常資料 | 完成設計並啟用 API，送出一筆自己準備的虛構資料 | 一次提交最多 1 次請求；逐欄核對原文 |
| 資訊不足 | 同一任務改用缺少關鍵資訊的原文 | 記錄模型是否承認不足，不能補造人物或數字 |
| 保存與重跑 | 成功後操作 API 開關以外、表單外的自訂控制項（若有） | 不應重新請求；結果須仍對應當次原文 |
| 新提交失敗 | 先成功，再提交空白／過長內容 | 舊成功結果清掉，錯誤獨立顯示 |
| 缺金鑰／服務失敗 | 移除本機設定後重啟或由教師模擬失敗 | 缺 key 應在請求前停止；模擬須標明不是實際服務故障 |
| Cloud 部署（必做） | 老師可開啟 App 網址；至少一筆雲端真實 API 成功，顯示當筆原文與結果 | 記錄網址、驗收日期、部署分支／入口、實際輸入輸出與請求數；本機或模擬不能取代 |

不能為了觀察故障而反覆打 API；拒答、未完成、空文字、解析／欄位失敗可由教師離線模擬。
**格式合格不代表事實正確；離線或假回應不代表模型成果。** 至少保留正常與資訊不足各一筆實際模型紀錄。
記錄實際 input、output、模型、日期、人工核對、問題與修正；失敗如實記錄，未測填「未測」。

## 8. 請求數與成本

起點與教師例均預設關閉 API；開啟後只有有效提交才請求，每次最多 1 次，max_retries=0。
規劃教師一次正常示範＝1 次；學生一次正常＋一次資訊不足＝2 次，額外修正重測另計。
學生可把這兩次安排在雲端，同時完成模型紀錄與部署驗收；已做本機測試後再測雲端，須另外計次。
不自動執行批次測試，不要求學生為了湊次數重複呼叫。若自加串流或第二個任務，需註明額外請求數。
6000 字元是課堂成本護欄，不是 token 上限；60 秒是網路等待設定，不是整段執行時間保證。
沿用 `OPENAI_MODEL=gpt-5.4-mini`，課前以教學帳號確認可用性，未驗證前不可宣稱帳號可呼叫。

## 9. 繳交內容與評分

繳交 GitHub 連結、Streamlit Community Cloud App 網址、可執行 App、requirements、自己的 README、設計與驗收紀錄，並完成 3～5 分鐘 Demo。
繳交期限與完整個人Demo時段以老師公告為準。

### 9-1. GitHub繳交位置與檔案

**請在自己的GitHub Repo根目錄建立 `Midterm Mini-Project` 資料夾，將期中專題相關檔案集中放入此資料夾。** 沿用自己的學期Repo，不必另建一個Repo；資料夾名稱請保留大小寫、空格與連字號。

以入口為 `app.py` 的專案為例：

```text
自己的 GitHub Repo/
└── Midterm Mini-Project/
    ├── app.py
    ├── requirements.txt
    ├── README.md
    ├── .gitignore
    ├── .env.example
    ├── .streamlit/
    │   └── secrets.example.toml
    ├── 第08週_課堂簡化版_專題設計與驗收紀錄.md
    └── sample_data/  （有使用範例資料時一併放入）
```

可將所選起點的內容複製到此資料夾後改造，或自行實作；只需完成所選路線，不必同時繳交JSON Schema與Pydantic兩版。
程式需要的其他模組、素材與測試紀錄也要一併提交，讓老師依README即可找到檔案並啟動。若保留教材連結，須改成自己Repo內的實際位置。
只提交 `.env.example` 與Secrets範例，不提交真正的 `.env`、`.streamlit/secrets.toml`、虛擬環境或金鑰。
完成後Commit／Push，並到GitHub確認 `Midterm Mini-Project` 內檔案齊全；老師從已登記的Repo查看此資料夾。App網址與雲端驗收紀錄寫在資料夾內的README，連結提供方式依老師公告。

### 9-2. README、Demo與評分

README 必含：使用者與問題、採用 JSON Schema／Pydantic 的理由、安裝／啟動、設定方式、輸入與輸出欄位、操作範例、App 網址與雲端驗收日期／結果、實測／未測項目、成本與限制。
Demo 依序說明問題→開啟雲端網址操作→逐欄查原文→設計決策與限制；可沿用既有真實測試紀錄，不要求為展示重複付費。
使用 AI 協助時簡記協助內容、自己修改與親自驗證事項；虛構測試資料要標示，不要求大量截圖。

| 項目 | 比重 | 評分證據 |
|---|---:|---|
| 功能完整度 | 30% | 一個明確任務在本機與Cloud可操作，成功與失敗分流，部署驗收完成 |
| LLM 使用品質 | 25% | 自己的 prompt／欄位設計、真 Structured Outputs、逐欄核對 |
| Streamlit UI | 20% | 輸入、送出、結果與錯誤清楚，不要求特定版型 |
| 安全與成本 | 10% | 金鑰保護、預設關閉、輸入限制、請求數說明 |
| README 與 Demo | 15% | 有老師可開啟的App網址與雲端驗收紀錄，可重現操作、說明測試限制與自己的設計 |

總分 100，期中專題占學期 20%。不用 starter 不扣分，選題不同不改最低標準。
金鑰外洩仍屬重大安全問題；不要把金鑰放進截圖、程式或 README。
